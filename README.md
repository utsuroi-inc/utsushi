# 写し / utsushi

Webページ全体を1枚の画像またはPDFとして保存するChrome拡張（Manifest V3）。

原本から取った控え＝写し、から。ページの現状に手を加えず、そのまま記録します。

- **通信ゼロ。** ページの内容もURLも画像も、外部に一切送りません。アカウントもテレメトリもありません
- **権限は3つだけ。** `activeTab` / `scripting` / `storage`。全サイトへのアクセス権は要求しません
- **ワンクリック。** アイコンを押したら即撮影。設定画面を挟みません

---

## インストール

配布物のzipを受け取った場合は、1から始めてください。

1. zipを展開し、`dist` フォルダを**消えない場所**に置く（ダウンロードフォルダに置いたままだと、後で消してしまいがちです）
2. Chromeで `chrome://extensions` を開く
3. 右上の「**デベロッパーモード**」をONにする
4. 左上の「**パッケージ化されていない拡張機能を読み込む**」を押し、`dist` フォルダを選ぶ
5. ツールバーに写しのアイコンが出れば完了（見当たらなければ、ツールバーのパズルピースのアイコンから固定できます）

> **フォルダを移動・削除しないでください。** 読み込んだフォルダの中身をChromeが直接参照しているため、消すと拡張も動かなくなります。

> デベロッパーモードがONの間、Chromeの起動時に「デベロッパーモードの拡張機能を無効にする」という確認が出ることがあります。閉じれば通常どおり使えます。

### ソースからビルドする場合

Node.js 20以上が必要です。

```bash
npm install
npm run build
```

`dist/` が生成されるので、上の手順4で選びます。開発中は `npm run watch`、型チェックは `npm run typecheck`。コードを変更したら、拡張カードの更新ボタン（⟳）を押してください。

## 使い方

**ツールバーの写しアイコンをクリック**（または `Alt+Shift+P`）すると、その場で全ページの撮影が始まります。右下に進捗が出て、撮り終わると新しいタブに結果が開きます。

- 撮影中にもう一度押すと**中断**します。中断してもページの表示位置は元に戻ります
- 結果のタブから **PNG / JPEG / PDF** で保存、または**クリップボードへコピー**できます
- 画像がとても大きい場合は自動で複数枚に分かれます。1枚ずつでも、まとめてでも保存できます（**PDFは分割されず1つのファイル**にまとまります）

### 設定

`chrome://extensions` → 写しの「詳細」→「**拡張機能のオプション**」から開きます。

| 項目 | 既定 | 効果 |
|---|---|---|
| キャプチャ待機時間 | 600ms | 1画面ごとの待ち時間。繋ぎ目がずれるときは長くする |
| 固定ヘッダーなどを自動で隠す | ON | 同じヘッダーが何度も写るのを防ぐ |
| 撮影前にページ全体を一度スクロール | OFF | 遅延読み込みの画像が写らないときに有効 |
| 画像形式 | PNG | 画像が分割されたときの「この部分を保存」で使う形式 |
| JPEG品質 | 0.92 | 0.5〜1.0 |
| PDFの用紙 | 画像サイズ | 画像サイズ（縦長1ページ）/ A4縦に分割 |
| ファイル名 | `{title}_{yyyyMMdd-HHmmss}` | `{title}` `{url_host}` `{yyyyMMdd-HHmmss}` が使える |

キーボードショートカットは既定で `Alt+Shift+P`。変更は `chrome://extensions/shortcuts` から行えます。

## 撮影できないページ

Chromeの仕様上、拡張機能が動けないページがあります。これらでアイコンを押すと、理由が表示されて撮影は始まりません。

- `chrome://` などChromeの内部ページ、拡張機能のページ、`about:`、`view-source:`
- Chromeウェブストア
- ローカルファイル（`file://`）は既定で不可。撮りたい場合は `chrome://extensions` → 写しの「詳細」→「**ファイルのURLへのアクセスを許可する**」をONにしてください

## 既知の制限

方式（1画面ずつ撮って繋ぐ）に由来するもので、v1では仕様として許容しています。

- **ページの中にある独立したスクロール領域**（`overflow: scroll` の内側）は、見えている範囲しか写りません
- **別ドメインのiframe**も可視範囲のみです
- **無限スクロールのページ**は、撮影を始めた時点の高さまでが対象です。全部撮りたい場合は、先に自分でスクロールして読み込ませてください
- **動画やCSSアニメーション**は、撮影した瞬間のコマが写ります
- **本文中のsticky要素**（追従するサイドバーや関連記事など）は、2枚目以降で空白になることがあります。困る場合は設定で「固定ヘッダーなどを自動で隠す」をOFFにしてください（代わりにヘッダーが何度も写ります）
- **撮影中に別のタブへ切り替えると中断します。** 撮影しているタブを表示したままにしてください
- Shadow DOMの中の固定要素は、隠す対象になりません
- スクロール位置をJavaScriptで制御しているページ（パララックスなど）では、狙った位置に止まらず繋ぎ目がずれることがあります
- 極端に長いページ（画面200枚分を超えるもの）は撮影できません

うまく撮れないときは、まず設定の**待機時間を長く**（800〜1200ms）してみてください。

### 設計の骨子

- **方式**：スクロール＆スティッチ（1ビューポートずつ撮って縦に連結）
- `chrome.debugger` を使えば1回のAPI呼び出しで全ページを撮れますが、「デバッグ中」のインフォバーが出てユーザー体験を損なうため採用していません
- **UI**：アイコンをクリックしたら即撮影。ポップアップは挟まない

### 開発上の制約（重要）

同種の拡張機能が既に存在しますが、機能が同じツールを独自に実装すること自体は問題ありません（著作権法10条3項：解法＝アルゴリズムは保護対象外）。ただし以下は厳守します。

1. **他拡張のソースコードを参照しない**（依拠性を生じさせない）
2. **他社の登録商標にあたる語を名称・コード・ドキュメントに使わない**（対象の語と根拠は `docs/legal-notes.md` §2）
3. **アイコン・レイアウト・素材を既存製品に寄せない**

根拠と詳細は `docs/legal-notes.md`、実装上の遵守事項は `docs/requirements.md` §12 を参照。
