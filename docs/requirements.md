## 1. 目的・概要

ワンクリック（またはショートカット）で、表示中のWebページ**全体**（スクロールが必要な範囲を含む）をキャプチャし、1枚の画像（PNG/JPEG）またはPDFとして保存できるChrome拡張機能（Manifest V3）を開発する。

ユースケース：
- クライアントサイトの現状記録（AIO/LLMO監査・改善提案のエビデンス）
- LP・デザインのアーカイブ
- 研修資料・マニュアルへの貼り込み素材の取得

名称の由来：縦に長い1枚画像＝巻物。同種製品の商標・意匠を想起させない独自の名称として選定（§12参照）。

## 2. スコープ

### 2.1 v1の対象
- ツールバーアイコンのクリック／キーボードショートカットによる全ページキャプチャ
- キャプチャ中の進捗表示
- 結果を新規タブ（拡張内ページ）で表示
- PNG / JPEG ダウンロード、PDF ダウンロード、クリップボードへコピー
- 固定要素（fixed/sticky）の二重写り防止
- 高DPI（Retina）対応
- 超巨大ページの自動分割出力
- オプションページ（形式、品質、待機時間、ファイル名テンプレート等）
- 日本語／英語のi18n

### 2.2 v2以降の候補（v1では実装しない）
- 注釈・トリミング等の編集機能
- 範囲選択キャプチャ
- クラウド保存・共有リンク
- ZIP一括ダウンロード
- Firefox / Safari 対応

### 2.3 対象外（実装しない）
- ページ内容の外部送信、アカウント機能、テレメトリ
- `chrome.debugger` を用いたキャプチャ方式（§6.4参照）

### 2.4 対象環境
- Chrome 最新安定版（MV3）／ Windows・macOS
- Edge等のChromium系は「動けば可」だが動作保証はしない

| 用語 | 意味 |
|---|---|
| セグメント | 1回の `captureVisibleTab` で得られる可視領域1画面分の画像 |
| 合成（スティッチ） | セグメントを縦に連結して全体画像を作ること |
| DPR | `window.devicePixelRatio`。キャプチャ画像はCSSピクセル×DPRの実ピクセルになる |
| 結果ページ | 拡張同梱の `result.html`。合成結果の表示とエクスポートを担う |

## 4. 機能要件

### FR-01 キャプチャの起動
- ツールバーアイコンのクリックで即キャプチャ開始（ポップアップは出さない）
- キーボードショートカット（既定：`Alt+Shift+P`、`commands` APIで変更可能）
- キャプチャ不可URL（§8.1）の場合は開始せず、理由を通知する

### FR-02 全ページキャプチャ処理
1. ページ寸法（`scrollHeight`等の最大値）、ビューポート寸法、DPR、現在のスクロール位置を計測する
2. `scroll-behavior: smooth` を一時的に無効化するCSSを注入する
3. 最上部から1ビューポートずつスクロールし、各位置で描画待機ののちセグメントを取得する
4. `captureVisibleTab` のレート制限（約2回/秒）を守るため、キャプチャ間隔は最低500ms以上を確保する（待機時間はオプション化、既定600ms）。クォータ超過エラー時は指数バックオフで1回リトライする
5. 最下段は端数になるため、合成時に重複分をクロップして正確に連結する
6. 完了後、元のスクロール位置・変更したスタイルをすべて復元する

### FR-03 固定要素の二重写り防止
- 2枚目以降のセグメント取得前に、computed styleが `position: fixed` または `sticky` の要素を `visibility: hidden` にする（1枚目には写す＝ヘッダーは先頭に1回だけ写る）
- キャプチャ完了後に必ず復元する
- オプションでこの処理をOFFにできる（既定：ON）
- 巨大DOMでの全要素走査コストに注意し、必要な最適化は実装者判断とする

### FR-04 遅延読み込み（lazy-load）対策
- キャプチャ開始前に `img[loading="lazy"]` を `eager` に変更し、デコード完了を待つ
- 各スクロール位置での描画待機（FR-02の待機時間）を併用する
- オプション「事前に全体をプリスクロールする」（既定：OFF）を用意する

### FR-05 進捗表示
- 拡張アイコンのバッジに進捗（例：`40%`）を表示する
- ページ右下に小さな進捗オーバーレイを表示する。ただし**キャプチャの瞬間は必ず非表示**にし、画像に写り込ませない
- キャプチャ中の再クリックはキャンセルとして扱う

### FR-06 結果ページ（result.html）
- キャプチャ完了後、新規タブで開き、合成画像を表示する（ズーム：全体表示／等倍の切替程度でよい）
- 操作：
  - **PNG保存**／**JPEG保存**（品質はオプション値）
  - **PDF保存**（§FR-08）
  - **クリップボードへコピー**（`ClipboardItem` / PNG）
- ファイル名はテンプレート（既定：`{title}_{yyyyMMdd-HHmmss}`）から生成し、OSで使えない文字はサニタイズする
- セグメントの受け渡し・合成の実装方式は §6.3 を推奨とする

### FR-07 超巨大ページの分割
- 合成キャンバスの安全上限（既定：高さ16,000実ピクセル、かつ総面積がChromeのcanvas上限未満）を超える場合、縦方向に複数枚へ自動分割する
- 結果ページでは分割画像を縦に並べて表示し、「個別保存」と「すべて保存（順次ダウンロード）」を提供する
- PDF出力は複数ページ化で吸収する（分割の影響を受けない）

### FR-08 PDF出力
- ライブラリはjsPDF等を**ローカルバンドル**する（MV3はリモートコード禁止）。ライセンスは §12.4 に従いMIT等の許諾的ライセンスに限る
- モード：
  - (a) 画像サイズに合わせた単一ページ（既定）。PDFの寸法上限（1辺14,400pt）を超える場合は自動で複数ページに分割
  - (b) A4縦に自動分割
- 用紙モードはオプションで切替可能

### FR-09 オプションページ
`chrome.storage.sync` に保存。項目と既定値：

| 項目 | 既定値 | 備考 |
|---|---|---|
| 画像形式 | PNG | PNG / JPEG |
| JPEG品質 | 0.92 | 0.5〜1.0 |
| キャプチャ待機時間 | 600ms | 200〜2000ms。実効下限500ms |
| 固定要素を自動で隠す | ON | FR-03 |
| 事前プリスクロール | OFF | FR-04 |
| PDF用紙 | 画像サイズ | 画像サイズ / A4 |
| ファイル名テンプレート | `{title}_{yyyyMMdd-HHmmss}` | `{title}` `{url_host}` `{yyyyMMdd-HHmmss}` を置換 |

### FR-10 i18n
- `_locales/ja` `_locales/en` を用意し、ブラウザ言語に追従する（既定文言は日本語で作成し、英語を併記）

## 5. 非機能要件

- **NFR-01 プライバシー**：ページ内容・URL・画像を一切外部送信しない。通信ゼロ。テレメトリなし（訴求点でもある）
- **NFR-02 権限最小化**：`activeTab` / `scripting` / `storage` のみを基本とする。ホスト権限 `<all_urls>` は使わない。`downloads` 権限は原則不要（結果ページの `<a download>` で保存する）
- **NFR-03 性能**：待機600ms設定時、約14,000CSSピクセル（約20画面）のページを25秒以内で完了する目安
- **NFR-04 メモリ**：セグメントは合成後すみやかに破棄する。合成は1回のみ行い、中間キャンバスを持ち回らない
- **NFR-05 復元保証**：エラー時・キャンセル時を含め、ページのスタイルとスクロール位置を必ず元に戻す（try/finally相当の構造にする）

## 6. 技術構成

### 6.1 コンポーネント
- `manifest.json`（MV3）
- **Service Worker**（background）：起動制御、`chrome.tabs.captureVisibleTab` の実行、レート制御、状態管理
- **Content Script**（`chrome.scripting.executeScript` で動的注入）：寸法計測、スクロール制御、固定要素処理、lazy-load対策、オーバーレイ表示
- **結果ページ**（result.html/ts/css）：セグメント合成（canvas）、表示、PNG/JPEG/PDF/クリップボード出力
- **オプションページ**（options.html/ts）
- `lib/`：jsPDF等の同梱ライブラリ

### 6.2 ビルド・言語
- TypeScript + esbuild（依存最小のビルドスクリプト構成）。`npm run build` → `dist/`、`npm run watch`
- 型チェック：`npm run typecheck`
- `dist/` を `chrome://extensions` の「パッケージ化されていない拡張機能を読み込む」で動作確認する

### 6.3 セグメントの受け渡し（推奨方式）
- Service WorkerはセグメントのdataURL（またはBlob）を**IndexedDB**に保存し、キャプチャIDを付けて結果ページを開く。結果ページがIndexedDBから読み出して合成し、完了後にレコードを削除する
- 代替：長寿命ポート（`chrome.runtime.connect`）での転送も可。`chrome.storage.session` はクォータ（既定約10MB）に注意し、主手段にはしない
- Service Workerでは `URL.createObjectURL` が使えない点に注意する

### 6.4 設計判断の背景（変更しないこと）
- **スクロール＆スティッチ方式を採用**する。CDP（`chrome.debugger` + `Page.captureScreenshot { captureBeyondViewport: true }`）なら1発で撮れるが、「デバッグ中」インフォバーが表示され、`debugger` 権限がユーザーに与える不安が大きいため不採用
- **ポップアップUIを持たない**。クリック＝即撮影のワンアクションが本ツールの体験の核
- **権限は最小**。`activeTab` はユーザー操作時のみ現在タブへのアクセスを許すため、この用途に十分

## 7. UI要件

- アイコン：巻物／縦長の紙をモチーフにした独自デザイン（16/32/48/128px）。既存の同種拡張を想起させる意匠（カメラ＋青系の丸アイコン等）は避ける（§12.3）
- 進捗オーバーレイ：右下固定の小型カード（アイコン＋%表示）。前述のとおりキャプチャ瞬間は非表示
- 結果ページ：上部に操作バー（PNG / JPEG / PDF / コピー）、下に画像。余白を活かしたシンプルな構成。ライト/ダークはブラウザ設定に追従（`prefers-color-scheme`）
- 文言はすべて `_locales` 経由で管理する

## 8. 制約・エラーハンドリング

### 8.1 キャプチャ不可のケース
- `chrome://` `edge://` `about:` `chrome-extension://` 各ページ、Chrome ウェブストア → 検知してユーザーに通知（バッジ＋通知 or アラート）
- `file://` はユーザーが「ファイルのURLへのアクセスを許可」を有効にした場合のみ可。無効時は案内を出す

### 8.2 既知の制限（v1では仕様として許容し、READMEに明記）
- ページ内の独立スクロールコンテナ（`overflow: scroll` の内部）は「見えている範囲」しか写らない
- クロスオリジンiframeも可視範囲のみ
- 無限スクロールページは「キャプチャ開始時点の `scrollHeight`」までを撮影対象とする
- CSSアニメーション・動画はキャプチャ瞬間のフレームが写る

### 8.3 エラー時の挙動
- どのフェーズで失敗しても：スタイル・スクロール位置を復元 → 取得済みセグメントを破棄 → 日本語で原因と対処を通知
- `captureVisibleTab` のクォータ超過は自動リトライ（1回）後、待機時間を増やす提案を表示

## 12. 法務要件（最優先の制約）

調査の詳細と根拠は `docs/legal-notes.md` を参照。以下は実装上の遵守事項。**本節に反する実装・記述は、他のどの要件よりも優先して回避する。**

### 12.1 コードの独立性 — LR-01
- **他のスクリーンショット拡張のソースコードを閲覧・参照・引用・複製しない。** Chrome拡張はローカルに展開されるため技術的には閲覧可能だが、閲覧した事実は著作権侵害の「依拠性」立証を容易にする
- 実装の参照先は、Chrome Extensions 公式ドキュメント、MDN、および本要件定義書に限る
- Claude Codeへの指示：既存製品の内部実装を推測して再現するのではなく、仕様（本書）から素直に実装すること

**根拠**：日本の著作権法10条3項により、プログラムの著作物の保護は言語・規約（インターフェース、プロトコル）・解法（アルゴリズム）に及ばない。機能が同一でも指令の表現が異なれば侵害にならない。よって「スクロール＆スティッチ方式」の独自実装は適法。制約はコード表現と素材の非流用に尽きる。

### 12.2 名称・商標 — LR-02
- **`FullPage` `Full Page` `GoFullPage` を、名称・ファイル名・クラス名・変数名・コメント・説明文・キーワードに使用しない**（`GOFULLPAGE` は Full Page LLC の米国登録商標。同社規約はメタタグ・隠しテキストでの使用も禁じている）
- 既存の同種拡張の製品名をストア掲載情報に含めない。「○○の代替」といった比較表現も使わない
- リポジトリ名・パッケージ名・拡張の内部名はすべて `makimono` 系で統一する

### 12.3 意匠・トレードドレス — LR-03
- アイコン、配色、結果ページのレイアウト、進捗表示の見せ方を、既存の同種拡張に寄せない
- スクリーンショット、イラスト、説明文などの素材を一切流用しない
- 迷ったら「見た目で取り違えられうるか」を基準にする

### 12.4 第三者ライブラリ — LR-04
- 同梱するライブラリはMIT / Apache-2.0 / BSD等の許諾的ライセンスに限る（GPL系は採用しない）
- ライセンス全文を `licenses/` に格納し、READMEとオプションページからリンクする
- MV3の制約によりCDN読み込みは不可。必ずローカルバンドルする

### 12.5 配布前チェック（ストア公開する場合のみ）
- [ ] 掲載情報（タイトル・説明・スクリーンショット・アイコン）に他社名・他社商標が含まれていない
- [ ] 説明文のキーワード反復が過剰でない（同一キーワードは5回未満を目安）
- [ ] 権限が `activeTab` / `scripting` / `storage` に収まっている
- [ ] プライバシーポリシーを用意し、「収集・送信するデータなし」を明記
- [ ] 単一目的（single purpose）の記述が明確

**参考**：Chrome Web Storeの重複コンテンツ規約は「同一開発者・関連アカウント・関係者による重複機能の複数出品」を禁じるもので、**無関係な開発者による競合拡張は重複コンテンツにあたらない**と明示されている。同種の拡張が既に存在すること自体は審査上の障害にならない。

本節は法的助言ではなく、実装上のリスク低減指針である。有償配布・大規模公開の段階では、知財を扱う弁護士のレビューを受けること。
